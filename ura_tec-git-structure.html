Git & GitHub 構造とデータの所在

「手元の隠しフォルダ (.git)」と「クラウド保管庫 (GitHub)」の分離構造

データフローと「お決まりの3行」
領域 1

作業ディレクトリ

画面で見えているファイル群。コードを書いたり編集したりする作業場。

場所: 通常のフォルダ
1. git add . ➔
領域 2

ステージング

「次のセーブに何を含めるか」を登録する荷造り台（インデックス）。

場所: .git/index（手元）
2. git commit -m "..." ➔
領域 3（中核）

ローカルリポジトリ

タイムマシン本体。過去の全履歴が圧縮保存されたPC内のセーブデータ保管庫。

場所: .git/objects/（手元）
3. git push ➔
領域 4

リモート保管庫

手元のセーブ履歴の完全コピー。共有とバックアップを担う外部倉庫。

場所: MS Azure サーバー群
クラウドへ反映完了
復元のメカニズムとトラブル時の挙動

⚡ 基本は「ローカル（.git）」から復元

全履歴が自分のPC内（.git）に揃っているため、ネット環境がなくても過去のどのコミット地点へも一瞬で戻せます。

git checkout <コミットID>

※確認が終わったら git switch main で最新状態へ即座に復帰可能。

🚨 .git フォルダを誤って消去した場合

手元のコードは残りますが、履歴管理機能は全滅します。しかし、事前に push してあればマイクロソフトのサーバーから完全復旧できます。

git clone https://github.com/...

※クラウド上のセーブデータからローカル環境を再構築。
